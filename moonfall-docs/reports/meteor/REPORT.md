# Meteor · MuzCruor

เปรียบเทียบกับ Arena บน main ที่ `b2f01e1` จากกล้องเล่นจริง ทั้งสกิลพิเศษ Meteor และท่าสุดท้ายของคทาเพลิงใช้เอฟเฟกต์ใหม่ ตัววาดเลือก AOE ชนิด `meteor` ที่ส่งเวลาตก 0.85 วินาทีมาจากเกม ท่าทุบพื้นของมอนสเตอร์ การกระแทกธาตุ และเหตุการณ์ภูเขาไฟใช้จังหวะของตัวเอง

| ช่วง | ภาพและสัญญาณการเล่น |
|---|---|
| เตือน | ขอบสว่างอยู่ที่รัศมีโจมตีจริงตั้งแต่เริ่มร่าย เงาและแนวความร้อนด้านในเปลี่ยนตามความคืบหน้าของ AOE |
| ตก | ก้อนหินผิวบะซอลต์หมุนบนวิถีเฉียงที่เร่งลง รอยร้าวเผยเนื้อร้อน หางพลาสมาแนบกับก้อนหินแล้วไหลเป็นควัน เถ้าและสะเก็ดถูกพัดย้อนตามวิถี |
| กระแทก | พื้นภาพยุบตรงกลางและยกที่ขอบ แผ่นเปลือกแตกมีผิวหน้า หน้าตัด และช่องว่างที่เผยความร้อน เศษวัสดุกระเด็น ตก กระดอนและหยุดตามระดับผิว มีแสงวาบสั้น คลื่นอากาศ และฝุ่นที่ขยายตามพื้น |
| หลังชน | ช่องแตกค่อย ๆ มืดลงตามอัตราเย็นตัวของวัสดุ เศษหินตกค้างและค่อย ๆ ยุบกลับ รอยบนบกอยู่ประมาณ 7 วินาที ส่วนผิวน้ำกระเพื่อมและไอน้ำจางในประมาณ 2.2 วินาที |

ใช้ MeshStandardMaterial สำหรับผิวหินและแผ่นเปลือก มี shader รอยแร่และหางพลาสมาที่ไหลด้วย noise texture ของเกม แผนที่ระยะถึงรอยแตกสร้างครั้งเดียวเมื่อเริ่มใช้ Meteor ในฉาก แล้วใช้ร่วมระหว่างพื้นกับก้อนอุกกาบาต แรงโน้มถ่วงของเศษวัสดุอยู่ที่ 760 หน่วยเกมต่อวินาทีกำลังสอง

ผิวดินเขตอาณาจักร ป่าต้องสาป น้ำแข็ง ทุ่งเถ้า และห้วงอเวจี ใช้สี ความลึกหลุม การกระเด็น ความหนืดของฝุ่น และการคายความร้อนต่างกัน น้ำเปิดเกิดไอและระลอก น้ำในเขตน้ำแข็งใช้ผิวน้ำแข็งแตก สะพานรับรอยไหม้ตามแนวพื้นไม้ การยุบตัวบนบกเขียนเฉพาะพิกัดความสูงของ vertex ใน Three.js โดยรวมรอยที่ซ้อนกันจากค่าพื้นเดิม และปรับขอบเขตการคัดแถวภูมิประเทศให้ครอบคลุมความสูงใหม่

High บนเดสก์ท็อปเก็บหลุมรายละเอียดสูงพร้อมกันได้ถึง 5 ชุด ชุดละ 21 แผ่นขอบและเศษหิน 27 ชิ้น โหมดประหยัดและมือถือเก็บได้ 3 ชุด ชุดละ 13 แผ่นและเศษหิน 13 ชิ้น เศษหินวาดด้วย instancing เอฟเฟกต์ที่เกินจำนวนชุดระหว่างรอลงพื้นยังมีวงเตือนและฝุ่นกระแทก การเปลี่ยนฉากคืน geometry, material, texture และ instance buffer ที่ Meteor เป็นเจ้าของ

## วิธีเทียบ

```sh
python3 src/tests/smoke-arena-meteor.py /path/to/reference/app/src/main/assets /tmp/meteor before high
python3 src/tests/smoke-arena-meteor.py app/src/main/assets /tmp/meteor after high
python3 src/tests/smoke-arena-meteor.py /path/to/reference/app/src/main/assets /tmp/meteor before low
python3 src/tests/smoke-arena-meteor.py app/src/main/assets /tmp/meteor after low
```

สคริปต์ใช้ Python Playwright และ Chromium เข้า Solo ผ่าน HTTP สร้างโลก seed 777 ใช้ตัวละครและเป้าหมายที่จุดเดิม คงแสง เวลา และรัศมีกล้อง แล้วร่ายผ่าน `castSpecial` จริง เดิน host และ renderer ที่ 30 tick/s วัดเฟรมที่เลือกด้วยการรออ่านหนึ่งพิกเซลจาก WebGL ระยะเวลาใน JSON จึงรวมงานทั้งฉากบนเครื่องเรนเดอร์ซอฟต์แวร์ วิดีโอประกอบจากจังหวะภาพที่วัด เก็บไฟล์ภาพกับวิดีโอนอก Git ตามกติกา repo

## ผลที่วัดได้

ภาพก่อนและหลังวัดจาก Chromium ผ่าน ANGLE/SwiftShader ที่ 900 × 520 สำหรับ High และ 800 × 450 สำหรับ Low โดย Low ใช้ Android user agent และ touch emulation ตัวเลขเป็นทั้งฉาก รวม terrain, shadow และ postprocessing ที่เปิดตามคุณภาพ

| คุณภาพ | เฟรมที่เก็บ | Draw calls ตอนตก | Draw calls ตอนชน | สามเหลี่ยมตอนชน | เวลามัธยฐานรวม readback (ms) | เฟรมชนรวม readback (ms) |
|---|---:|---:|---:|---:|---:|---:|
| High | 23 | 296 → 294 | 303 → 299 | 8,516,721 → 8,519,668 | 3,213 → 3,254 | 3,478 → 3,253 |
| Low | 5 | 240 → 237 | 244 → 241 | 7,187,672 → 7,188,370 | 1,885 → 1,973 | 1,885 → 2,097 |

การนับ draw calls เป็นจำนวนคำสั่งวาดจริง ส่วนเวลามีทั้งงาน CPU งานเรนเดอร์แบบซอฟต์แวร์และการรอ GPU การทดสอบ Low เก็บห้าจังหวะ จึงใช้บอกต้นทุนในฉากนี้ได้จำกัด ประสิทธิภาพบน GPU มือถือจริงและ frame pacing ระหว่างการเล่นต่อเนื่องยังไม่ได้วัด

- สกิลพิเศษที่ทดสอบมีรัศมี 230, damage ก่อนหักเกราะเวท 145.728, burn 9 และคูลดาวน์ 20 วินาที ทั้งสอง build ให้ HP ของเป้าหมายตรงกันทุกเฟรมที่บันทึก เหลือ 2,342.249 จาก 2,400 ในภาพกระแทก
- ท่าคทาเพลิงใช้การร่ายจริงแยกต่างหาก รัศมี 220 และ delay 0.85 วินาทีใน loadout ทดสอบ การส่ง AOE ผ่านตัวเข้ารหัสและถอดรหัสจริง 7 snapshot สร้างแรงกระแทกหนึ่งครั้ง
- ที่จุดทดสอบ พื้นภาพยุบลึกสุด 43.46 และยกขอบ 20.47 หน่วย พื้นชนที่จุดศูนย์กลางคงอยู่ที่ 0 ตลอดทดสอบ ทดสอบหลุมทับกันและใช้ pool ซ้ำ 4 รอบแล้วพิกัดพื้นทั้งบัฟเฟอร์กลับมาตรงกับต้นฉบับทุกค่า
- ทดสอบพื้นทั้ง 5 เขต น้ำและสะพาน ตรวจการคืนทรัพยากรที่ effect เป็นเจ้าของบน High ได้ 40 จาก 40 รายการ และ Low ได้ 26 จาก 26 รายการ ทั้งสองโหมดไม่พบ JavaScript หรือ shader error ในการร่ายและการเรนเดอร์
- `node --check` ผ่านทั้งโมดูลและสคริปต์ inline ที่ build แล้ว สำเนา HTML ที่ deploy ตรงกับผล build ชุด smoke ออนไลน์เปิด host/client สองบริบทและผ่านเส้นทาง event, snapshot, FX budget และ teardown
